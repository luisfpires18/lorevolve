# UI components

One page. Read it before any UI change, and reuse a row before writing something new.
The design contract is `LOREVOLVE_VISUAL_REFACTOR.md` section 5. This page lists what exists.

Paths are under `src/LorEvolve.Web/src/`. A class names the file and line of its first rule under `styles/`.

## Rules

- Screens live in `pages/`. Shared pieces live in `components/`. Saving and loading live in each feature's `api.ts`. Pure helpers live in the feature folder or `lib/`.
- One job per file. No web source file goes over 300 lines (`lineLimit.test.ts`, CI job "Line limit", no exceptions). Split a file along its jobs.
- One component per repeated element. Differences are props, not copies.
- Before you write a part, search this page and extend the row that fits. Add a row only when none fits.

## The one inline pattern

Three screens confirm in place of their button instead of through `confirmAction`, by the owner's decision on #255 (2026-11-16): Universe Settings (`.settings__confirm`, also used by Collaborators and Connected apps), Publish (`.publication__confirm`) and Trash (`.trash__confirm`). Each one opens beside the control it confirms and keeps the page around it in view (the universe name, the list of items and what each loses), shows its own error in place when the call fails, and returns the focus to its own button. A modal would cover what the author is confirming. Every other confirmation uses `confirmAction`. A new inline confirm reuses one of these classes; there is no fourth one. Draw it with `InlineConfirm` (#414): `look` names one of the three classes, the title, notes and actions go in as props and children, the error shows in place as an alert (`actions` sits the action row after it, as Trash does), and Escape keeps, as Keep does, except while the action runs. Escape never reaches an `ActionMenu` or `Drawer` around the panel, busy or not. The owner moves the focus with `useConfirmFocus`: open moves the focus to the panel through `panelRef`, close returns it to the button.
